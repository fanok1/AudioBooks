### 1.2. Контракт интеграции и точки расширения

1. **Регистрация и навигация.** Добавляется строка `Provider` с уникальными `sourceId`, `prefValue`, `prefKey`, адресами каталога/жанров/авторов/чтецов и экземпляром `SourceParser`. Настройки и переключение источников используют `Provider.values()`. Отсутствующий индекс людей задаётся `null`; ссылки людей в карточке могут при этом работать. Для открытия внешних ссылок дополняются `AndroidManifest.xml` и, при необходимости, алиасы `Url.canonical`.
2. **Карточка и описание.** `BookPOJO` хранит название, URL, cover, автора/чтеца и их ссылки, жанр, серию, длительность, счётчик комментариев и поле `reting`. `DescriptionPOJO` дополняет аннотацию и сведения книги. Поле `reting` исторически используется неоднородно; просмотры нельзя выдавать за пользовательскую оценку.
3. **Пагинация и ошибки.** `listing`, `pageUrl`, `searchResults` возвращают `ProviderPage`: элементы, настоящий `hasMore`, состояния `OK/EMPTY/ERROR/TIMEOUT/BLOCKED`. `ListingCursor` и `SearchSession` сохраняют отдельные курсоры, устраняют повторы, не должны принимать challenge за пустой каталог. Нужно проверить вторую и последнюю страницы, а не просто наличие параметра `page` в URL.
4. **Поиск.** `searchUrl(BOOKS,…)` обязателен; поиск авторов и исполнителей допускает `null`. Поиск нескольких сайтов идёт параллельно с ограничением времени: в `SearchebleModel` — 10 секунд на источник; «На других сайтах» в `OtherSourceModel` — также 10 секунд. Страница поиска, требующая загрузить описание каждой найденной книги для cover/времени, заметно хуже полноценной выдачи.
5. **Меню и фильтры.** Адаптер задаёт `optionsMenu`, `sortUrl`, `hasSort`, `genreOf`, `inGenre`, `listsDuration`. Существующие XML-меню можно переиспользовать только при совпадении смысла пунктов. DLE-сортировки часто требуют **POST и правильных ключей сессии**, GET-параметр может игнорироваться. Локальный фильтр времени работает по длительностям уже загруженных карточек и автоматически просматривает ограниченную порцию — до четырёх страниц за проход; он не равен серверному поиску по всему каталогу.
6. **Периоды — отдельная оговорка.** `ListingFilters.periods/periodOf/withPeriod` перечисляют существующих поставщиков через `switch`, соответствующих методов в `SourceParser` нет. Новый источник может предложить фиксированные пункты «за неделю/месяц» через `sortUrl`, но для общего переключателя периодов потребуется небольшое общее изменение `ListingFilters`. Обещать это одной строкой в `Provider` было бы неверно.
7. **Плеер и загрузка.** `tracks` должен вернуть непустой список `AudioPOJO`: URL, название, секунды, при необходимости `timeStart/timeFinish` для глав внутри единого файла/потока. `mediaHeaders` задаёт контекст аудиозапросов. В `DownloadUtil` уже есть progressive MP3 и HLS/Media3, Referer применяется также к дочерним запросам. Наличие HLS само по себе не требует нового плеера. Однако скачивание в кэш, перемотка и экспорт отдельных файлов — разные проверки: `ChapterExtractor` явно не поддерживает HLS с fMP4 initialization segments. В [DownloadIds.java](../app/src/main/java/com/fanok/audiobooks/download/DownloadIds.java) единая загрузка общего потока реализована **для HLS**; progressive MP3 получает отдельный ID и cache key на каждый ordinal главы. Один MP3 на всю книгу с несколькими clip-главами потребует дополнительного общего решения, а не только установки границ времени.
8. **Экосистема книги.** Серии, рекомендации, комментарии, другие озвучки и поиск той же книги на других источниках предусмотрены интерфейсом. Значения по умолчанию часто пустые: это техническая возможность подключения, но не доказательство полноценной интеграции. В текущем коде комментарии читаются не у всех 13 источников; например, для ИзиБук/Книгоблуда/Отрубина/Полекниг возвращается пустой список.
9. **Сеть.** `SiteHttp`: Jsoup, проверка TLS, cookie jar по хосту, ограниченный размер ответа, распознавание известных challenge. Универсального исполнения JavaScript страницы здесь нет. JSON API доступен из `fetch/tracks`, но нужно явно согласовать его с контрактом `Document`, а не переносить чужой `SourceManager`. Истечение подписей URL требует повторного получения плейлиста; нельзя сохранять временную подпись как постоянную личность книги/главы.

Основные файлы: [SourceParser.java](../app/src/main/java/com/fanok/audiobooks/source/SourceParser.java), [Dle.java](../app/src/main/java/com/fanok/audiobooks/source/Dle.java), [ProviderPage.java](../app/src/main/java/com/fanok/audiobooks/search/ProviderPage.java), [SearchSession.java](../app/src/main/java/com/fanok/audiobooks/search/SearchSession.java), [DownloadUtil.java](../app/src/main/java/com/fanok/audiobooks/util/DownloadUtil.java), [ChapterExtractor.java](../app/src/main/java/com/fanok/audiobooks/util/ChapterExtractor.java), [SiteHttp.java](../app/src/main/java/com/fanok/audiobooks/net/SiteHttp.java), [SettingsFragment.java](../app/src/main/java/com/fanok/audiobooks/fragment/SettingsFragment.java).

## 2. Как проверялись сайты

Использованы исходные списки, исходный код проекта, страницы самих сайтов, их HTML/JavaScript и запросы к плейлистам/API. HTTP проверялся напрямую из этой среды, с обычным desktop User-Agent; поисковый веб-инструмент использовался дополнительно. Если результаты различались, ниже приоритет у явно описанного прямого запроса. HTTP 200 с JS-проверкой не считается доступным каталогом. Ошибка одного транспорта не доказывает, что сайт закрыт для всех пользователей.

Для подходящих кандидатов проверялись каталог, его продолжение, поиск, жанр, меню сортировок, страница книги, плейлист и небольшой фрагмент аудио. `206 audio/mpeg` с `Content-Range` и сигнатурой MP3 подтверждает доступ к проверенному файлу и частичное чтение, но **не доказывает**, что весь каталог доступен, все книги полные или Android-интеграция уже работает. Если длительность известна только из метаданных, это прямо указано. Для HLS отдельно важны manifest, segment и key.

**Размеры каталогов.** API `total` — число, заявленное API на дату проверки. Оценка по пагинатору вычисляется как `(последняя страница − 1) × обычное число карточек + карточки последней страницы`. Проверка первой, второй и последней страниц не доказывает непрерывность всех промежуточных страниц; такая оценка не равна переписи уникальных полных аудиокниг. Суммировать размеры разных сайтов нельзя: совпадения произведений, озвучек и аудиофайлов значительны.

### 2.1. Россия, Украина и Европа: отдельная проверка доступности

**Критерий принят:** возможность работы без VPN/proxy в этих регионах — преимущество источника. Проверять нужно цепочку **каталог → поиск/API → книга → плейлист → MP3 либо HLS manifest/key/segments**, а не только главную страницу. Нельзя считать сайт заблокированным по одной ошибке или объявлять доступным по всей стране по одному удачному запросу.

Для независимой проверки использованы [официальный API Check-Host](https://check-host.net/about/api) и его [актуальный список узлов](https://check-host.net/nodes/hosts). Диагностические запросы выполняли сами узлы сервиса; VPN/proxy в настройках проекта не включался. У локального Python-процесса переменные `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` отсутствовали. Проверены следующие точки по географии, заявленной сервисом:

| Регион | Узлы | Сети |
|---|---|---|
| Россия | `ru1`, `ru2`, Москва | AS14576 и AS210644 |
| Украина | `ua1`, Хмельницкий; `ua3`, Киев | AS201094 и AS13335 |
| Европа | `de2`, Ланген; `fr2`, Париж; `pl2`, Варшава | AS212000, AS12876, AS214379 |

**Это серверные измерительные точки, а не полный охват домашних и мобильных операторов.** Украинский `ua3` относится к Cloudflare AS13335; его нельзя считать независимым доказательством условий обычного украинского абонента. Даже два успешных узла в стране не гарантируют доступность в других сетях, отсутствие DPI или стабильность через месяц. Европа здесь представлена Германией, Францией и Польшей, а не всеми странами континента.

В то же время [удалённый HTTP-запрос к каталогу API](https://check-host.net/check-report/54510836k17) и [к API плейлиста](https://check-host.net/check-report/54510838k447) дали 200 во всех семи точках. В текущей среде эти API ранее фактически разобраны как JSON и из плейлистов получены рабочие MP3. Это положительный, но частичный результат для международной доступности; не подтверждение, что браузерный антибот одинаково легко проходится у всех пользователей.

Удалённые проверки не воспроизводили этот контекст, поэтому их 403 нельзя объявить блокировкой России или Украины. Региональный доступ с правильными заголовками пока не доказан.

Для Archive.org найдены более полезные свежие данные. 29.10.2026 [RU AS51604, ER-Telecom, 16:08 UTC](https://api.ooni.io/api/v1/raw_measurement?measurement_uid=20261029160820.841846_RU_webconnectivity_549812eb1338ad46) показал HTTP 200 и `accessible=true`; [RU AS48073, 16:39 UTC](https://api.ooni.io/api/v1/raw_measurement?measurement_uid=20261029164002.327838_RU_webconnectivity_5855a3da8fd56476) — timeout, `anomaly=true`, **`confirmed=false`**, при успешном TCP 443. Есть успешные HTTP-наблюдения [UA AS34867](https://api.ooni.io/api/v1/raw_measurement?measurement_uid=20261029065110.536430_UA_webconnectivity_8bb01fd6fd095f21) и [DE AS57043](https://api.ooni.io/api/v1/raw_measurement?measurement_uid=20261029170629.489969_DE_webconnectivity_3e7de2b0872eecfe). [OONI отдельно объясняет различие аномалии и подтверждённой блокировки](https://ooni.org/support/interpreting-ooni-data/).

**Влияние на выбор:** ни одному кандидату не присваивается безусловное «работает без VPN во всей России, Украине и Европе». У трёх рекомендованных сайтов есть положительная транспортная проверка выбранных сетей, у Lis10book — также API, но полная цепочка воспроизведения из домашних/мобильных сетей ещё не доказана. У Голосом добавлена неопределённость украинского редиректа; у Bookish/АудиокнигиВсе учитывается зависимость от Archive.org. Основной порядок 1–7 пока сохраняется: данных недостаточно, чтобы честно пересортировать их по географической надёжности. Перед выпуском региональная проверка полной цепочки без VPN должна стать обязательным условием допуска выбранного провайдера.

Почему порядок такой: Aknigi24 требует относительно прямого HTML/JSON→MP3 адаптера и даёт время в поиске. Lis10book выигрывает API, размером и комментариями, но требует проверки качества времени. Audiokniga.one и Библус дают полезную навигацию без догрузки каждой карточки. Audiokniga-online.ru ниже из-за размера, хотя по меню он один из самых подходящих. Slushat и Pro дают большой охват, но меньше доказанных глобальных сортировок. Bookish понижен именно из-за нерешённой сортировки; Golosknig — из-за протокола и недоступных записей; Голосом — из-за отсутствия подтверждённых социальных выборок.

Вторая страница **поиска** полностью проверена на распространённом запросе у Lis10book; у остальных подтверждены работа поиска и отдельная пагинация каталога, но не все сочетания поиска/жанра/сортировки/периода на второй странице. Это требуется проверить при реализации, и успешная страница 2 каталога не подменяет такую проверку.

### 1. Aknigi24.com

**Доступность и маршруты.** Все ниже вернули HTTP 200 обычным Requests без входа:

- [Главная](https://aknigi24.com/), [страница 2](https://aknigi24.com/?page=2), [последняя страница 1342](https://aknigi24.com/?page=1342).
- [Поиск «метро»](https://aknigi24.com/search?q=%D0%BC%D0%B5%D1%82%D1%80%D0%BE): полноценные карточки с обложкой, продолжительностью, автором/исполнителем, жанром; не текстовые ссылки с обязательным N+1 detail.
- [Фантастика, фэнтези](https://aknigi24.com/genre/fantastika-fentezi), [глобальный рейтинг](https://aknigi24.com/?sort=rating), [рейтинг внутри жанра](https://aknigi24.com/genre/fantastika-fentezi?sort=rating). Жанровый рейтинг меняет первые книги относительно обычной жанровой страницы.

**Объём.** На обычных первых двух страницах по 21 карточке, на странице 1342 — 17; на странице 1343 карточек нет. Оценка по пагинации `1341×21+17 = 28 178` записей. Это не полный обход всех страниц. Меню отдельно показывает 8908 записей в фантастике/фэнтези и 6236 в ужасах/мистике; эти числа нельзя суммировать в уникальный объём, поскольку категории могут пересекаться. [Каталог и жанры](https://aknigi24.com/genres).

**Метаданные.** [Город тысячи богов](https://aknigi24.com/book/gorod-tysiaci-bogov-kozin-oleg-buldakov-oleg) содержит автора Кожин Олег, исполнителя Булдаков Олег, обложку, жанр, год 2020, 10 ч 17 мин, описание, рейтинг и комментарии. В обычных карточках есть серии, например «Цикл о Грегоре и Арнольде» у «Рейса молочного фургона». Встроенный JSON плеера даёт `bookId=31443`, `chapterBase=https://aknigi24.com/book/31443/chapter/`, массив `chapters` из 19 объектов `{n,d}`; длительности глав в секундах, например первая 341. У этой книги серии нет: это отсутствие значения у конкретной книги, а не отсутствие поддержки серий на сайте.

**Сортировки.** В глобальной выдаче и жанре доступны GET `sort=rating|title|new|duration`, `dir=asc` для обратного направления. В поиске есть дополнительная релевантность. Это рейтинг, название, новизна и длительность; отдельные глобальные сортировки «по обсуждениям» и «по просмотрам» в изученных меню не обнаружены. Не следует изображать рейтинг как просмотры.

**Аудио и скачивание.** [Первая глава](https://aknigi24.com/book/31443/chapter/1) без входа: `200 audio/mpeg`, `Content-Disposition: inline; filename="1.mp3"`, полный размер 2 728 273 байта, начало `ID3`. Отдельный запрос `Range: bytes=0-1023` вернул **206**, `Content-Range: bytes 0-1023/2728273`, 1024 байта. Путь главы работает как самостоятельный HTTP media URI, браузер/JS для получения URL не нужен. Достаточно распарсить встроенный JSON и создать по AudioPOJO на главу. В основном запросе сервер устанавливает анонимные cookies, но первый media запрос работал без предварительного посещения книги.

**Плюсы:** duration+cover уже в поиске и лентах; явные длительности глав; простые MP3 и byte ranges; серверные сортировки не требуют session POST; жанры с количествами; пользователи могут оставлять отзывы.

**Минусы/границы:** обсуждаемость и просмотры как отдельные сортировки не подтверждены; проверена одна полная структура книги и первая глава, не весь каталог. Совпадение конкретных произведений с другими библиотеками ожидаемо и не означает тождество каталогов. Сайт сам описывает автоматическое наполнение из открытых источников.

### 2. Lis10book — сильный кандидат при работе через JSON

Главная `https://lis10book.com/` прямым HTTP-запросом вернула 200 и 62 679 байт HTML Next.js. Веб-инструмент на том же адресе видел проверку JavaScript; отдельная страница книги тоже вернула 200 с заголовком проверки и 6845 байт. Поэтому HTML не годится как единственный транспорт. При этом проверенные ниже JSON-маршруты доступны без сессии и регистрации.

- [Каталог, страница 1](https://lis10book.com/api/books?audio=full&page=1): HTTP 200 JSON, `total=84774`, `page=1`, `limit=24`, `totalPages=3533`. [Страница 2](https://lis10book.com/api/books?audio=full&page=2) вернула `page=2` и другие записи.
- [Популярные](https://lis10book.com/api/books?sort=popular&audio=full&page=1): первыми пришли «Железное пламя», «Ониксовый шторм». [Страница 2](https://lis10book.com/api/books?sort=popular&audio=full&page=2) начинается другой книгой; это серверная глобальная пагинация.
- [Рейтинг](https://lis10book.com/api/books?sort=rating&audio=full&page=1) вернул другую последовательность; [страница 2](https://lis10book.com/api/books?sort=rating&audio=full&page=2) также рабочая. Поля рейтингов в карточках различаются: `livelibRating`, `uknigRating`; не следует представлять их как единую шкалу без нормализации.
- [Положительный поиск](https://lis10book.com/api/books?q=%D0%96%D0%B5%D0%BB%D0%B5%D0%B7%D0%BD%D0%BE%D0%B5&audio=full&page=1) вернул три результата по слову «Железное». Параметр — `q`; `search=` вернул обычные новинки и **был молча проигнорирован**. Запрос `q=Стругацкий` вернул пусто: поиск по фамилии автора на этом примере не доказан.
- [Жанры](https://lis10book.com/api/genres): массив из 144 объектов. [Фантастика](https://lis10book.com/api/genres/fantastika?audio=full&page=1): HTTP 200 JSON с `genre` и `books.items`.
- [Метаданные книги](https://lis10book.com/api/books/zheleznoe-plamya): авторы, чтецы, жанры, обложка, `totalDurationSec=25200`, номер и состав серии, альтернативные озвучки, признаки `isClosed`, `minTier`, `audioSource`, `fragmentUrl`, список глав. Полная длительность взята из метаданных и не сверена с суммой аудиофайлов.
- [Комментарии](https://lis10book.com/api/books/zheleznoe-plamya/comments?limit=10&offset=0): HTTP 200, `total=25`, `comments`, `hasMore`; есть автор, дата, текст, ответы.

**Сортировки: существенная оговорка.** Живой HTML и [штатный JS](https://bookish.site/engine/classes/js/dle_js.js) показывают пять вариантов: `date`, `rating` (подпись «популярности»), `news_read` («посещаемости»), `comm_num` («комментариям»), `title`. Cookies сортировки не установлены. Поэтому наличие пунктов и предполагаемый протокол доказаны, **работоспособность переключения и ранжирование по обсуждаемости не доказаны**. Нельзя заявлять полностью готовый drop-in источник до разрешения этого поведения. Возможно потребуется браузерная проверка или выяснение серверной обработки POST; причина не установлена.

**Плюсы:** большой каталог, богатые карточки/поиск, простой открытый MP3 плейлист и Range; отдельные автор/чтец/серия/комментарии. **Минусы:** не подтверждена работа меню сортировок; внешние archive.org файлы могут удаляться; размер каталога включает отдельные озвучки и повторы. Прямое скачивание из media URI доказано, отдельная кнопка «Скачать» не тестировалась.

### 9. Golosknig.com

**Доступность, объём и навигация.** [Главная](https://golosknig.com/), [страница 2](https://golosknig.com/index/page2/), [последняя 2486](https://golosknig.com/index/page2486/), [жанры](https://golosknig.com/genres/), [фантастика](https://golosknig.com/genre/fantastic/) — 200. **Плеер требует AJAX AES.** Живая [pl2.js?v=9](https://golosknig.com/templates/skin/sweetnew/js/pl2.js?v=9) берёт анонимный `LIVESTREET_SECURITY_KEY` со страницы, кодирует JSON строку штатным CryptoJS AES password-форматом, вызывает `POST /ajax/mbid/{bid}` с `bid`, `hash`, стандартным `security_ls_key`. Ответ содержит AES `res`, JSON `items`, `version` и `fstate`. Это штатная логика открытого плеера, без входа.

Проверены два реальных AJAX ответа:

- `bid=58475` («Иван Великий») → 200, один item, 1233 секунды, `time_from_start=0`, `time_finish=1233`. Расшифрованный URL — signed MP3 `r1.akniga.club/s/b/58475/...mp3?res=...&expires=...`; Range дал **206 audio/mpeg**, `bytes 0-1023/19723955`, ID3.
- `bid=92055` («Ячейка 21») → 200, **64 главы**, сумма `duration=37060` секунд; первая `0..704`, последняя `36815..37060`. Media URI — **один большой MP3** `r1.akniga.club/s/b/92055/...mp3?...`, Range **206 audio/mpeg**, `bytes 0-1023/592957875`, ID3. Главы не отдельные файлы: нужно повторять общий URI и сохранять `timeStart/timeFinish`; иначе приложение будет скачивать один и тот же большой файл 64 раза или терять границы глав.

**Ограничение доступности каталога.** [1984](https://golosknig.com/1984-oruell-dzhordzh), одна из первых популярных книг, вернула 200 с metadata, но прямо показывает **«Аудиокнига доступна на Литрес»**, `sweetPlayer` и локальный MP3 отсутствуют. Значит 29 830 — размер каталога, а не число воспроизводимых книг. Адаптер должен различать unavailable, а не считать отсутствие player ошибкой разметки.

**Плюсы:** живой большой каталог, длительность и cover в поиске, жанры, популярность с периодами, Range, полноценные временные метки глав. **Минусы:** AES AJAX сложнее открытого JSON; один большой MP3 требует clip-интеграции и разумного download dedup; частичная недоступность известных книг; рейтинг и обсуждаемость не подтверждены; signed URI надо обновлять. Штатный пароль алгоритма не секрет пользователя; цель — воспроизвести обычный открытый веб-плеер.

**Почему это условный кандидат для текущего проекта:** `AudioPOJO` и плеер умеют временные границы, но `DownloadIds.forBook` объединяет главы по потоку только для HLS. Для progressive MP3 формируются `chapter/<ordinal>` с разными cache key. Поэтому один общий MP3 с 64 clip-главами нельзя просто передать как 64 обычные MP3-загрузки: понадобится расширить общую модель загрузки/кэша/удаления и проверить экспорт. Это конкретное отступление от пожелания «только новый адаптер». Если общее изменение нежелательно, практичнее заменить эту позицию на АудиокнигиВсе с явно описанным обогащением поисковых карточек. Первые семь позиций не имеют обнаруженной необходимости такого изменения.

### 10. Голосом — богатые карточки; Аудиополка как связанный резерв

[golosom.org](https://golosom.org/), [жанры](https://golosom.org/genres), [жанр фантастики](https://golosom.org/genre/fantastika-fentezi), [поиск](https://golosom.org/search?q=%D0%9F%D1%83%D1%88%D0%BA%D0%B8%D0%BD), [страница 2](https://golosom.org/2), [проверенная книга](https://golosom.org/book/vojna-mirov-13) — 200. Главная содержит 21 карточку, последняя страница `/4452` — 7: ориентир по пагинации **около 93,5 тыс. записей**, не точный подсчёт уникальных произведений. У обоих карточки сразу содержат обложку, автора, чтеца, жанр, время, а при наличии — цикл; есть связанные страницы авторов, исполнителей и циклов. Это полезнее многих DLE-каталогов, где длительность надо загружать для каждой карточки отдельно. HTML доступен без аккаунта и JS. У Голосом адреса семантические `/book/slug`, `/author/slug`, `/performer/slug`, `/series/slug`; у Аудиополки — числовые сущности, включая `/voice/ID/` и `/series/ID/`.

У одной и той же «Войны миров» обнаружены **одинаковые `bookId=144479`, 27 глав, общая длительность 23 342 с и идентичные аудио-URL** `r7.audioknigi.xyz/…mp3?md5=…&expires=…`; сумма длительностей глав точно равна общей. Это сильное подтверждение общей записи и общей зависимости от медиахоста, но не доказательство единого владельца или полного тождества всего каталога.

**Ограничения:** URL имеют подпись и срок действия, их надо обновлять перед воспроизведением/скачиванием; вечное сохранение URL не подходит. Публичные сортировки рейтинга, популярности и обсуждаемости в проверенных HTML **не найдены**. На проверенной странице нет комментариев и рейтинга. «Новые» выдаются сервером. Поэтому оба уступают audiokniga-online.ru по полноте привычного меню. В основной десятке выбран Голосом: семантические адреса удобны для навигации и устойчивого сопоставления; Аудиополка остаётся альтернативной оболочкой той же проверенной записи. Включать оба ради числа источников не рекомендую.

**Интеграция:** отдельный HTML-парсер списков и сущностей, извлечение JSON `App.playerInit`, сборка подписанных MP3 и длительностей в `AudioPOJO`, обновление ссылок при открытии. Это близко к существующим XSPlayer-провайдерам, но имя конструктора и схема полей требуют своего разбора. По сравнению с АудиокнигиВсе ниже он даёт длительность прямо в поиске и существенно больший видимый каталог; дополнительная уникальность аудиозаписей относительно уже подключённых источников не измерена.

Реальный [запрос автора Tolstoy](https://librivox.org/api/feed/audiobooks/?author=Tolstoy&format=json&extended=1&coverart=1&limit=10) вернул200 и русскую запись **ID210, «Childhood — Детство»**, 28 разделов, `totaltimesecs=12637`, `3:30:37`, автора, жанр, чтеца и обложку. [Книга](https://librivox.org/childhood-russian-by-leo-tolstoy/) связана с MP3 на Archive.org. Проверка выявила противоречие: язык книги `Russian`, язык её первого section `English`, поэтому язык надо брать с уровня книги и учитывать качество старых метаданных. MP3 и размер русскоязычного каталога здесь не проверялись. Параметр `language` не документирован этим API; нельзя молча предполагать серверную фильтрацию по нему.

**Вывод:** технически чистый резерв для классики с другой аудиотекой, но не равноценная замена современным русскоязычным каталогам по подборкам и социальным сортировкам; место в основной десятке без отдельной проверки масштаба и медиа пока не обосновано.

### Что считать дублем, а что — только пересечением

- Домены из реестра текущих 13 источников, включая подтверждённые алиасы, не являются новыми кандидатами. Несколько `baza-knig.*` или `izibuk.*` не нужно превращать в несколько интеграций.
- `knigorai.com` при живой проверке перенаправляет на уже подключённый `poleknig.com`: исключён как отдельный источник.
- `biblus.org` и `m.biblus.org` вернули одинаковую главную и один набор книг: один кандидат.
- `audiokniga.one` и `audiokniga-one.com` имеют разные страницы, ID, данные и плееры; сходство названия не доказывает, что это зеркала.
- У `golosom.org` и `audiopolka.club` совпала последовательность найденных новых книг, а у одной книги — ID, 27 глав, длительность и сами подписанные MP3. Для планирования это одна сильно пересекающаяся семья; полнота совпадения каталогов и общий владелец не установлены.
- Одна и та же проверенная озвучка на `audioknigivse.ru` и `slushkinvsem.ru` использует один Archive.org-файл. Это доказанное пересечение, но не доказательство, что все их каталоги идентичны.

## 5. Что проверять при реализации выбранных 6–7

Исследование позволяет выбрать источники; до объявления каждого из них полноценной интеграцией нужны следующие проверки на самом адаптере и Android-приложении:

1. Главная, жанр, автор, чтец, цикл: переходы и пагинация, реальные первая/вторая/последняя страницы, остановка на конце; сохранение фильтра/жанра при смене порядка.
2. Поиск по названию, автору, названию с кириллицей и знаками; пустой результат и страница 2 распространённого запроса. Cover и длительность должны соответствовать конкретному результату; неподдерживаемый поиск людей возвращает `null`, а не каталог новинок.
3. Для каждого пункта меню — сравнить **порядок ID книг**, а не HTML-хеш страницы с рекламой. Обязательно проверить POST, cookies, правильное направление сортировки, повторное открытие «Новые» после рейтинга. Не показывать «Обсуждаемые», если сервер молча вернул новинки.
4. Несколько книг разных лет и жанров, короткая и длинная, полная и заблокированная/платная. Сверить заявленную длительность с плейлистом; обрабатывать удаление и фрагмент явно. Один работающий MP3 не подтверждает все книги сайта.
5. Получить аудио, начать с нуля, перемотать далеко вперёд, возобновить запрос с ненулевого Range. Сохранять исходные границы глав, порядок и идентичность при обновлении подписей.
6. Загрузить книгу, отключить сеть, проверить офлайн-воспроизведение, восстановление прогресса и удаление/повторную загрузку. Для HLS — manifest/segments/keys и отдельный экспорт глав; для большого единого MP3 — нарезку по временным границам.
7. Истёкшая подпись, сменившийся CDN, redirect, 403/429, timeout, challenge HTTP 200. Ошибка источника не должна стирать уже показанную выдачу или сохраняться как «книг больше нет».
8. Серии, комментарии, альтернативные озвучки и «На других сайтах»; выбранный источник должен участвовать в общем поиске и открываться по внешней ссылке. Тестировать и «особые» книги без автора/времени/обложки.

Для регрессий уже есть примеры в [SourceParserDefaultsTest](../app/src/test/java/com/fanok/audiobooks/source/SourceParserDefaultsTest.java), тестах адаптеров и [fixtures](../app/src/test/resources/fixtures). Новые fixture-тесты должны проверять реальные варианты страниц/плейлистов, а не только повторять селекторы реализации. Сборка приложения и прогон Android-плеера в рамках этого исследования не выполнялись: изменения ограничены документацией.
