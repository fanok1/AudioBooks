# Задачи подготовки и интеграции источников

Основание: [анализ и проект решений](plan.md). **Это будущие задачи реализации; создание данного списка не означает выполнения рефакторинга.** Все флажки намеренно оставлены открытыми. Текущая пользовательская задача — подготовка анализа и плана — завершается отдельно от этого backlog.

Пути Java ниже относительны `app/src/main/java/com/fanok/audiobooks/`; JVM-тесты — `app/src/test/java/com/fanok/audiobooks/`, device-тесты — `app/src/androidTest/java/com/fanok/audiobooks/`. Новые имена классов являются предложениями. Сначала сверять актуальное дерево: номера схем и реализация могут измениться после даты плана.

Правило размера: одна задача/подзадача меняет одну проверяемую возможность, обычно 2–5 production/test файлов плюс fixtures. Перечисленные семейства файлов не следует изменять все одним коммитом. Если срез затрагивает больше пяти логических файлов, сначала выделить поддерживающую подзадачу с теми же критериями совместимости. Перенос legacy-сайта разбит в T04 и повторяется в T19.

## Проверочные команды

Запуск из корня в PowerShell; доступность JDK/SDK проверяется по [howto.md](../docs/howto.md).

- **F(class):** `.\gradlew.bat :app:testDebugUnitTest --tests 'com.fanok.audiobooks.<package>.<Class>Test'` — подставить существующий или добавленный класс, не оставлять placeholder в отчёте.
- **U:** `.\gradlew.bat :app:testDebugUnitTest`.
- **G:** `.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`.
- **D:** `.\gradlew.bat :app:connectedDebugAndroidTest` на подготовленном устройстве.
- **P:** фиксированный сценарий/устройство/сборка, запросы и активные соединения локального fixture-сервера, Perfetto/gfxinfo/meminfo; сравнение с T02.

Для сетевого теста нужен управляемый сервер с задержками, redirect, cookies, Range и счётчиком активных вызовов; простой `python -m http.server` для Range-сценариев не подходит. Fixtures не подтверждают живую доступность — перед включением конкретного источника нужен небольшой отдельный live smoke.

**Зависимости:** T13–T14. **Объём:** два M-среза.

**Файлы:** resolver, `service/MediaPlayerService`, `service/PlaybackErrorPolicy`, tests; затем download resolver integration и tests.

- [ ] Playback refresh сопоставляет главу по identity: reorder с тем же count не продолжает другую главу; неопределённость сохраняет checkpoint и сообщает ошибку.
- [ ] Download refresh обновляет signed URI, включая HLS зависимые адреса; одновременные запросы книги объединяются, retry budget конечен.
- [ ] Частичный download возобновляется только при подтверждённом соответствии ресурса; изменение версии контента не смешивает байты.

**Проверка:** F policy/resolver, D player; локальный сервер с expiry/401/403/410, reordered playlist, changed ETag/length, сменой CDN.

### T16. Мигрировать хранение identity без потери старых данных

**Зависимости:** T02, T14. **Объём:** M на подзадачу; только последовательные schema changes.

**Файлы:** T16a Room entities/DAO/schema migration и `MigrationTest`; T16b `AudioListDBModel` и sync tests; T16c backup mapping/validator и round-trip tests.

- [ ] Upgrade от существующих поддержанных схем сохраняет favorites/history/checkpoints/localUri/ordinal и добавляет новые поля без destructive migration текущей версии.
- [ ] Legacy/`v1` IDs и alias rows остаются читаемы; повторный backfill не меняет identity; orphan exported rows сохраняются.
- [ ] Backup round-trip/SAF/offline восстановлены; описан forward fix/резервная копия, downgrade не объявлен безопасным откатом.

**Проверка:** D `MigrationTest`/`SyncChaptersRetainedTest`, F backup tests, фактический offline restart на мигрированной библиотеке T02.

### T17. Один progressive resource для нескольких глав

**Зависимости:** T14–T16. **Объём:** три M-среза.

**Файлы:** T17a `download/DownloadIds` + mapping/tests; T17b `util/DownloadUtil`, download status/UI/tests; T17c `util/DeletionPlanner`, export ownership/tests.

- [ ] N clips общего MP3 создают один download/cache key и размер ресурса учитывается один раз; выбор главы честно показывает загрузку общего файла.
- [ ] Chapter clipping/checkpoint сохраняются при offline/restart/обновлении подписи, разные query-addressed файлы не сливаются.
- [ ] Удаление одной главы сохраняет общий ресурс остальных; экспорты выбранных глав не присваиваются соседям и не требуют N загрузок файла.

**Проверка:** F identity/deletion/export; D `DeletionExecutorTest`, `ExactKeyExportTest`, `ReExportTest`; локальный сервер подтверждает число запросов/байтов.

### T18. Проверить HLS и общий MP3 на новых адаптерах

**Зависимости:** Audiokniga.one — T14–T15; Golosknig — также T16–T17. **Объём:** отдельные M-срезы адаптеров, fixtures и registration.

- [ ] Audiokniga.one: genre/menu semantics, manifest/key/segment context, expiry, TS/AES offline/export; неоднозначные меню не выданы за доказанные.

- [ ] fMP4: текущая неподдержка экспорта видна пользователю и не портит cache; если требуется поддержка, выделена отдельная задача с initialization-segment fixtures и device acceptance до включения export.
